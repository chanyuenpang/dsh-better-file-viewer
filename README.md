# Better file viewer

独立的 DSH「文件」会话视图。新增会话视图，不改动、接管或替换原侧栏。

## 安装（无需克隆源码）

适配基线：DSH Desktop/Web **0.2.2-rc.1**。在 DSH Desktop 的插件管理器中选择安装，输入预构建包地址：

```text
https://github.com/chanyuenpang/dsh-better-file-viewer/releases/download/v0.1.11/dsh-better-file-viewer-0.1.11.tgz
```

普通 Web profile 可使用：

```sh
dsh plugin --profile web add https://github.com/chanyuenpang/dsh-better-file-viewer/releases/download/v0.1.11/dsh-better-file-viewer-0.1.11.tgz
```

安装包已包含浏览器构建产物，无需本地构建或手动复制文件。插件市场条目正在提交；收录后可搜索 `dsh-better-file-viewer`。是否需要刷新或重启以插件管理器的结果为准，不会自动重启 DSH。

Office 预览依赖宿主的 `officeToPdf` 服务；本插件不安装 Office 转换运行时。不支持的宿主版本未经过兼容性验证。

## 功能

- 文件导航与预览同屏，可放在左、右、上、下；鼠标拖动或键盘方向键调整分隔。左右采用文件树，上下采用横向层级分栏（一级一列、各列独立滚动），降低目录导航的竖直高度需求。
- 左右树中，点击目录名称可展开/收起并浏览该目录图片；箭头也可展开/收起。层级分栏中点击文件夹进入下一列，点击已展开的文件夹或列标题可收起后续层级。
- 空目录及没有图片的目录，预览内容区留白，不显示“空文件夹／没有图片”或零图片标题；读取中、失败和目录截断仍有明确反馈。
- 顶部仅保留一条紧凑图标栏：布局入口显示方向图标，点击仍使用原生选择器；文件夹图标切换目录显示。回根、刷新、返回目录及图片翻页都有图标、tooltip和可访问名称，不再重复显示完整目录/路径文字行。
- 文件树、层级分栏和图片卡片名称前有类型图标；文件夹区分展开/收起，未知文件使用通用图标。
- 目录图片按可见区域加载缩略图；点击图片进入独立预览，可前后浏览、返回目录。先点击图片/图片区获得焦点，Ctrl + 加号（或Ctrl+=）/减号调整大小：目录中改变缩略图尺寸，单张图片中改变图片缩放。也支持鼠标悬停图片区时按住Ctrl滚轮：向上放大、向下缩小，无需先点击。不增加工具栏按钮。
- 非 JSON 文件使用独立 fork 的官方预览：文本、Markdown、代码、图片、HTML、PDF、Excel/CSV/TSV、Office 转 PDF。格式支持和安全策略继承固定版本实现。
- JSON 使用 super-json-editor 的结构导航，默认只读、无 Raw 编辑；按用户最新要求完整保留默认 object/表格/控件/配色/装饰，仅隔离样式作用域和适配预览容器尺寸。
- 四种布局均限制在当前会话视图可用区域内：文件树和预览各自滚动，外层不共同滚动。只在文件视图隐藏聊天输入区，保持编辑器挂载和草稿不变。
- 优先消费原生发给 better-files 的 viewRequest。对已切换文件 tab、却未传入定位请求的客户端，增加只观察可信本地文件点击的短期地址交接：不阻止或替换原导航，同一会话及 Conversation occurrence 的文件视图挂载后取回地址。0.1.4 的真实点击已由用户确认可用，运行时也记录到目标请求消费、正确选中文件及官方预览资源地址。
- 支持中英文，外层文件视图使用 DSH 主题；SJE 按用户要求保留原默认配色。布局方向是插件自己的浏览器偏好。

入口：有内容的会话顶部，与「聊天 / 轨迹 / 上下文」同级的「文件」。窄窗口可能收进官方的更多菜单；空白会话是否显示视图导航遵循官方会话页。

## 边界

- 只读：不保存、重命名、删除或新建文件。不注册模型工具或新的 Host 文件 API。
- 文件根目录取自当前会话 cwd。目录限制、文件权限和大小上限由 DSH 文件服务执行。
- 缩略图最多四个并发，单张 8 MiB；更大的图片可点击后使用官方分支的完整预览。
- JSON 结构浏览上限 16 MiB；非法 JSON 显示原文与解析错误，不伪造空对象。
- 目录手动刷新。非 JSON 预览的文件变更观察沿用官方资源机制；JSON 用工具栏刷新。
- Office 转换要求当前 DSH 提供 officeToPdf；无服务时显示官方缺失服务提示。
- 页面切换会释放当前预览与目录请求；切换四向布局不重新建立预览。
- 未在浏览器完成的交互不得仅凭安装或 Slot 注册宣称验证通过，参见交付记录。

## 开发

Node 版本应满足构建依赖要求。工作区依赖安装无需执行安装脚本：

```text
pnpm install --ignore-scripts
pnpm run build
pnpm test
```

已提交的 vendor/dsh 是固定版本 0.2.2-rc.1 npm 构件；下载/校验方式见 scripts/fetch-vendor.mjs。
JSON 源码快照包含文件哈希；更新时执行 scripts/snapshot-editor.mjs <source-directory>，再检查差异。
构建脚本只生成本项目的 client*.js、.build 和依赖许可证；不修改 DSH 或上游 editor。

安装使用 DSH 插件管理器，选择本项目目录作为 bundle。只插入 better-file-viewer 一行，不覆盖任何现有条目。

## 架构

- src/client.jsx：会话文件页、树、图库、JSON 和独立预览 occurrence。
- src/core.mjs：地址、布局、JSON、并发和生命周期的可测试核心。
- scripts/fork-preview.mjs：带上游锚点断言的隔离适配，失败即停止构建。
- scripts/build.mjs：本地编译所需官方 primitives/store，宿主 React 保持 external；PDF/Excel/frontmatter 保持自包含懒加载。
- betterFiles.preview Factory 独立拥有 betterFiles.document 等子 Slot；服务、locale 和 CSS 标识均与官方侧栏分开。

原侧栏继续运行未改动的官方组件，本插件不使用 sidebarRight/sidebarRightTabs，也不从注册表抓取官方组件实例。

## 0.1.9 直接打开文件后的目录加载（2026-11-13）

- 用户报告从会话直接打开文件后，子目录长期显示loading。实时Client诊断确认workspaceFilesHandleStable=false：每次读取ctx.remote.workspaceFiles得到的traced服务句柄引用不同，不能直接作为React异步加载生命周期依赖。
- 旧代码在请求消费/确认后父组件重渲染时，把新服务引用传入目录组件，触发effect清理、取消所有在途祖先目录请求；重新setup却只载入cwd，已经消费的定位请求不再调度祖先，因而子目录停在loading。
- 文件服务改为每个FilesView稳定memo的轻量转发层，实际操作时再读取当前服务，并保留方法receiver、参数和AbortSignal；引用变化不再取消目录请求，同时避免固定保留过期服务句柄。JSON/缩略图也不会因此无故重读。
